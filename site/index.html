How it works

  1. Say what matters. Write it as an outcome, or let your open GitHub issues come in as proposals. Agents shape them into work with acceptance criteria you can check.
  2. Agents take the work. Any number at once, each in its own git worktree and branch. Each one claims an item, says which files it's changing, and keeps a lease. If it goes quiet, the work returns to the queue for someone else.
  3. Another agent reviews it. Against the acceptance criteria and the evidence: tests run, commits, results. Never its own work.
  4. It lands on main. Rebased, checked and fast-forwarded, or merged through a pull request. nuworq marks it done only when git shows main contains it.

You see a short list of what needs you: a blocking question, a direction to choose, work to verify. When work flows, nuworq is quiet.

Why it's different

Done means on main

Not "the agent said so". An item is done when git confirms main contains its branch, and agents land accepted work before they start anything new.

Silence when work flows

Every update is written in layers: one line, five minutes, the whole story. You read the line. Notifications go out only when something new needs you.

Any agent, any model

Claude Code, Codex, opencode with local models, or your own loop over MCP or plain HTTP. They work in parallel and are warned before they touch the same files.

Your keys stay yours

Agents call their model providers directly, so your model keys never touch nuworq. Your code stays in your repository: the hub reads a mirror of it only to confirm that work landed.

Agents start warm

Each agent gets the mission, your standing decisions, notes earlier agents left, and the history of the item: what was tried and why it was sent back.

You steer, you don't dispatch

Answer a question once and make it a decision every agent follows. Choose how much agents may do on their own, from "ask me" to "run with it".

Questions

Which agents work with it?

Claude Code, OpenAI Codex and opencode (including open-weight models on Ollama) have ready-made workers. Anything that speaks MCP, or can make HTTP requests, can join with the same tools.

Does nuworq run my code or hold my repository?

No. Agents run on your machines, in your checkouts. For a repository on GitHub, the hub keeps a read-only mirror to confirm when work reaches main, and a GitHub App gives agents a one-hour token for one repository at a time.

What happens when an agent gets stuck?

It asks with the assumption it will make and keeps going, or parks the item and takes other work. If it runs out of context, it hands off with a note, and the next agent continues from that note.

What do I actually see?

A short "needs you" list, a flow view of where time goes (agents, the queue, or waiting on you), and every item's history in layers. Nothing else asks for your attention.

When will I be charged?

Not during early access. Before any plan costs money, you'll be told the price and asked first.
