# Audit: secure (#701)

Part of #676. Done on 2026-11-02 by claude-e174, which built none of the code it covers. It starts from #468's pass (2026-11-01; 0af01e5 is the last commit before it) and reads the 141 commits since, then the current code paths end to end. Four read-only reviews ran in parallel: identity and access; the git proxy, webhooks, the GitHub App and outbound requests; what open source adds (CI, releases, signing, update, the plugin, the repository's contents); and the git history. Each finding of medium or higher was then re-read at its lines by the auditor ("checked" below). The threat model is docs/SECURITY-MODEL.md.

Nothing here contains a working exploit or a secret value. Nothing was run against a live hub, GitHub or Stripe.

## Checked and sound

- **Workspaces.** Each has its own database, `Auth` and cookie path, and tickets work only in their own workspace. `AGENT_ROUTES` keeps agent tokens off human routes. Project scope is checked on every agent op, clone credential and route. Every human op checks `PERSON_CAN`. The minter cap (#629) and runner tokens (#656) hold, and removing a workspace clears its installations, plans and grants (#728).
- **Push proxy.** Only the exact `refs/heads/<held item's branch>` passes; main, tags, deletes, other branches and signed pushes are refused, and any refused ref refuses the whole push. Seen live in #704. The hub's token goes only to GitHub, and relayed headers are filtered. Upload-pack is refused.
- **Webhooks.** HMAC is compared in constant time, an App delivery reaches only its bound workspace, replays are ignored, fork PRs are ignored, and Stripe's signature has a time tolerance and applies once.
- **Outbound.** Addresses are resolved once and pinned, so DNS rebinding can't steer them. Redirects aren't followed, IPv4-mapped, NAT64 and 6to4 addresses are covered, and a shared hub gives preconditions no credentials (apart from finding 3).
- **CI.** The one workflow runs on `pull_request` and `push: main`, with no `pull_request_target`, no secrets and no cache. It has `permissions: contents: read`, actions pinned by SHA, and no attacker text in `run:`.
- **Updates.** https or loopback only; sha256, then ed25519 against the pinned key; the same key and named commit; no rollback.
- **The signer's checks.** It signs only an approved tag on main and GitHub's own build, compared byte for byte.
- **The plugin.** It runs the installed `nuworq mcp` from the `release` ref, with no hooks and nothing fetched at runtime.
- **The repository.** SECURITY.md, CONTRIBUTING.md and LICENSE are in place, and the only email in the docs is security@.
